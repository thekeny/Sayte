# PyQT Project

### 1. Описание

Название: Sayte (Say Note)

Запуск в Windows
```
pip install -r requirements.txt
python app.py
```

(По умолчанию) Ctrl+Alt+R начинает запись с микрофона, повторное нажатие останавливает её

### 2. Пользовательский путь

1. Запуск приложенния, работа в фоне и отображения в трее
2. При нажатии горячей клавиши появляется окно и начинается запись голоса
3. Повтороное нажатие горячей клавиши останавливает запись
4. Записанное аудио начинате обработку и преобюразование в текст в фоне через Whisper
5. Создается новая заметка с сказаным текстом, которая автоматически сохраняется в БД SQLite
6. По иконке в трее или запуску exe открывается основное приложение со списком всех заметок
7. В основном приложении можно:
- Просматривать и редактировать содержимое заметки
- Искать заметки по содержимому
- Добавлять теги и фильтровать заметки
- Удалять ненужные заметки
- Редактировать заметки с помощью запросов к ИИ-провайдеру
8. При выборе ИИ редактирования отправлять текст с введеным промптом к провайдеру и последующие принятие/отклонение изменений

### 4. Технологический стек

Язык: Python 
GUI: PyQT6
Распознование: faster-whisper
Запись аудио: sounddevice
Вызов по горячей клавише: RegisterHotKey Windows через ctypes и события Qt.
Сочетание Ctrl+Alt+R срабатывает по нажатию клавиши R (К в русской раскладке).
Если сочетание занято другим приложением, Sayte показывает ошибку регистрации.
База данных (хранение заметок, тегов, промптов, настроек и API-ключа): SQLite3
Обработка текста*: OpenRouter или любой OpenAI-совместимый API
HTTP-Запросы: requests/httpx
Сборка приложениня: PyInstaller
Зависимости: requirements.txt

* - Требует подключение к сети и доступ в интернет

### 11. Разделение файлов

- `app.py` — запуск приложения и создание главного окна.
- `ui/main_window.py` — главное окно, виджеты и обработчики действий пользователя.
- `audio/recorder.py` — запись и остановка звука с микрофона.
- `transcription/whisper.py` — преобразование записи в текст через Whisper.
- `database/database.py` — запросы к SQLite: заметки, теги и настройки.
- `ai/provider.py` — запросы к ИИ-провайдеру и получение ответа.
- `config.py` — общие значения и настройки приложения.

Модули записи, распознавания, хранения заметок и трея реализованы для MVP.
Модули ИИ остаются заготовками. Интерфейс вызывает методы сервисов и
показывает результат, а сами сервисы не создают окна. Распознавание и
загрузка модели выполняются в рабочем потоке, результат передаётся через
сигналы PyQt. Запросы к SQLite выполняются в главном потоке.

Для дизайна можно создавать окна в Qt Designer: например, сохранить главное
окно как `main_window.ui`, а окно настроек как `settings_window.ui`. Загружай каждый
файл через `uic.loadUi` в соответствующем классе окна. В `.ui` хранятся
расположение и свойства виджетов, а в Python — подключение сигналов и действия.
Пути задаются строками, например `ui/note_window.ui`. Запуск выполняется
из папки `sayte`. Другие окна добавляются в `ui` отдельными `.ui`-файлами
и Python-классами с обработчиками.

Файлы внутри модулей разделены по назначению:

- `ui/main_window.py` — главное окно; `settings_window.py` и
  `provider_window.py` — настройки; `recording_window.py` — состояние записи;
  `preview_window.py` — просмотр ответа ИИ; `tray.py` — системный трей.
- `audio/recorder.py` записывает звук, `utils/hotkey.py` обрабатывает
  глобальную горячую клавишу.
- `transcription/whisper.py` отвечает за модель, `transcription/worker.py` —
  за запуск распознавания в фоне.
- `ai/provider.py` обращается к API, `ai/presets.py` описывает промпты,
  `ai/worker.py` выполняет запрос в фоне.
- `database/database.py` отвечает за подключение и создание таблиц;
  `notes.py`, `tags.py`, `settings.py` и `presets.py` — за запросы
  к соответствующим данным.

Окна ИИ-провайдеров и предпросмотра ИИ, а также модули ИИ и пресетов
пока остаются заготовками. Главное окно, редактор, настройки,
диалог назначения хоткея и окно
записи загружают `.ui`-файлы из `ui`. Карточки заметок и кнопки тегов
используют отдельные `.ui`-шаблоны; индикатор звука размещён в форме записи
как пользовательский виджет. В Designer размещаются виджеты, в Python
подключаются сигналы и вызываются методы других модулей. База и сервисы
не зависят от окон: их можно проверять отдельно от интерфейса.
