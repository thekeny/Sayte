# Защита проекта QT

## Как будут оцениваться ваши проекты

### 1. Общие сведения

Во время обучения в Яндекс Лицее вам предстоит написать несколько проектов. Вы можете выполнять их самостоятельно или в группе (не больше 2-х человек). Проект по модулю PyQT — индивидуальный.

Как результат выполнения проекта вы должны предоставить своему преподавателю:

- **Задание проекта** — его следует согласовать с преподавателем до начала работы;
- **Программный код** с необходимыми комментариями, пояснениями и ресурсами;
- **Пояснительную записку** — документ, описывающий суть проекта, его особенности и прочие моменты;
- **Презентацию** — если вы проводите защиту проекта;
- **Видео** — при необходимости, например, для проекта PyGame.

Оценка за проект учитывает как саму реализацию задачи, так и оформление и представление проекта.

### 2. Оценка проекта

Разработанный вами проект оценивается по следующим критериям:

| Критерий | Оценка | Комментарий |
| --- | --- | --- |
| Объём программного кода | 15 | 15 баллов даётся за 500 и более строк. 12 — за 300. Далее пропорционально. Учитывается только содержательный код, в оценку не входят, например, карты уровней, если они включены в код. |
| Чистота кода | 5 | Оценивается PEP 8, константы в коде, copy-paste, говорящие имена переменных и так далее. |
| Качество проектирования | 20 | Используются ли классы, модули и прочее. Если код написан очень примитивно, то оценка снижается. |
| Применённые технологии | 20 | Реализованы ли практически все изученные в модуле технологии. |
| Оригинальная идея | 10 | — |
| Соблюдение сроков | 15 | Соблюдение сроков каждого этапа проекта. Даже учитывая сжатые сроки, просим вас разумно распределить своё время для работы над проектом, не откладывая всё на последний день. |
| Защита | 10 | Качество защиты проекта. Допуск к защите возможен только при условии выполнения всех этапов проекта до даты защиты. |
| Премия | 5 | — |
| Работоспособность | [0.25, 0.5, 0.75, 1] | Значение коэффициента выбирается из предложенного списка в зависимости от того, работает ли проект, реализует ли все заявленные функции и т. д. |

**Примечание:** критерии с баллами в сумме дают 100; работоспособность учитывается отдельным коэффициентом.

### 3. Оценка представления проекта

Значительный вес в оценку проекта вносит его защита — **10 баллов**.

Оценивается презентация, то, как вы рассказываете о работе, а также как отвечаете на вопросы преподавателя и одногруппников.

В презентации должны быть следующие разделы:

- **Титульный слайд:** название проекта, ФИО автора/авторов;
- **Введение:** идея проекта, для решения каких задач он создан;
- **Описание реализации:** структура (классы) и особенности приложения, какие технологии использовались;
- **Заключение:** выводы по работе, возможности для доработки и развития.

При оценке представления проекта **НЕ учитывается гармоничность оформления видео и презентации**.

### 4. Как сдавать проект

- **PyQT.** Папку с проектом заархивировать (`zip`, `rar`) и выложить на доступный файлообменник, например, Яндекс.Диск. Ссылку на файл предоставить преподавателю и приложить в качестве решения задачи.

### 5. Соблюдение сроков

При работе над проектом учащиеся должны соблюдать, а преподаватель отслеживать соблюдение следующих этапов проекта (названия условные):

1. Описание проекта.
2. Задание (ТЗ).
3. ТЗ + Часть задания выполнена.
4. Код + Работающая часть проекта.
5. Код + Работающая часть + Черновик пояснительной записки и презентации.
6. Код + Пояснительная записка + Презентация + Почти всё работает.
7. Всё готово.

Перед началом работы над проектом, за 1–2 недели, преподаватель назначит для каждого этапа проекта дату, когда он должен быть выполнен.

**Пример:**

| Этап | Дата |
| --- | --- |
| Создание команд. Описание проекта | 25.03.2024 |
| Задание (ТЗ) | 28.03.2024 |
| ТЗ + Часть задания выполнена | 01.04.2024 |
| Код + Работающая часть проекта | 04.04.2024 |
| Код + Работающая часть + Черновик пояснительной записки и презентации | 08.04.2024 |
| Код + Пояснительная записка + Презентация + Почти всё работает | 11.04.2024 |
| Всё готово | 16.04.2024 |

При достижении каждого контрольного срока преподаватель отмечает его выполнение (1) или невыполнение (0) каждым учащимся. В сумме за соблюдение всех сроков учащийся получает **15 баллов**, или **15/7 балла за каждый пункт**. В итоге все указанные пункты должны быть выполнены, иначе проект не может считаться завершённым, но баллы ученик получит только за те из них, которые были выполнены в срок.

*Даты в таблице приведены как пример, а не как актуальный график проекта.*

### 6. Применённые технологии

Для получения **20 баллов** за блок «Применённые технологии» в проекте должны быть использованы практически все изученные в модуле технологии. А именно:

1. Используется `requirements.txt` для управления зависимостями.
2. В приложении реализовано несколько форм.
3. В приложении используются:
   - Все изученные виджеты.
   - Дополнительные виджеты.
   - Стандартные диалоги.
   - Картинки.
   - Файлы `txt` или `csv`.
4. Работа с базами данных:
   - Несколько таблиц в БД.
   - Чтение из БД.
   - Запись в БД.
   - Изменение данных в БД.
5. Приложение собрано в единый исполняемый файл (`exe`).
